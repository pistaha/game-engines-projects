# Защита лабораторной: dvizki 3

## 1. Что представляет собой проект

`dvizki 3` - это десктопная версия алхимической сцены, перенесенная из проекта `dvizki 2`, где логика была ближе к VR-взаимодействию. В новой версии сохранена основная идея: игрок берет ингредиенты, помещает их в котел, затем ложкой запускает проверку рецепта. Отличие в том, что управление полностью адаптировано под desktop: клавиатура, мышь/тачпад и центральная точка прицела вместо VR-контроллеров.

Главная цель проекта - показать, что одна игровая механика может работать в двух формах управления:

- `dvizki 2`: VR-подход, где предметы берутся руками/контроллерами.
- `dvizki 3`: desktop-подход, где предметы выбираются лучом из центра камеры и удерживаются перед игроком.

## 2. Основной игровой цикл

1. Игрок ходит по комнате от первого лица.
2. В центре экрана есть точка-прицел.
3. Если точка наведена на бутылку или ложку, ПКМ берет предмет.
4. Повторное нажатие ПКМ отпускает предмет.
5. Если удерживаемая бутылка физически касается `IngredientZone` внутри котла, она исчезает и добавляется в список ингредиентов.
6. Рецепт не проверяется сразу после добавления бутылок.
7. Проверка происходит только когда игрок держит ложку и касается ею `StirZone`.
8. Если рецепт правильный, запускается успешный эффект.
9. Если рецепт неправильный, котел краснеет.
10. В обоих случаях бутылки возвращаются на стартовые места, чтобы можно было попробовать снова.

## 3. Управление

- `WASD` - перемещение.
- Мышь/тачпад - обзор камерой.
- `Q` и `E` - поворот персонажа влево/вправо с клавиатуры.
- `ПКМ` - взять предмет под центральной точкой или отпустить удерживаемый предмет.
- `E` или `F` - взаимодействие с книгой, если точка наведена на книгу.
- `LeftArrow` и `RightArrow` - листание страниц книги.
- `Escape` или `B` - закрыть книгу.
- `T` - запустить движение NPC Erika.

## 4. Архитектура кода

### DesktopSceneBootstrap

Файл: `Assets/Scripts/Desktop/DesktopSceneBootstrap.cs`

Это стартовая настройка desktop-версии. Скрипт автоматически проверяет сцену после загрузки и добавляет нужные desktop-компоненты, если они отсутствуют:

- `FirstPersonCC` - контроллер игрока.
- `PlayerInteraction` - клавиатурные взаимодействия.
- `DesktopGrabber` - захват предметов ПКМ.
- `ClickCollector` - обработка кликов по книге/страницам.
- `InteractionPromptUI` - центральная точка.
- `EventSystem` + `InputSystemUIInputModule` - чтобы работала UI-книга.

Также он отключает старые 3D TMP-тексты книги, потому что в desktop-версии книга сделана как плоское UI-меню.

### FirstPersonCC

Файл: `Assets/Scripts/Player/FirstPersonCC.cs`

Это контроллер игрока от первого лица:

- двигает персонажа через `CharacterController`;
- обрабатывает мышь/тачпад;
- добавляет поворот через `Q/E`;
- отправляет луч из центра камеры для клавиатурного взаимодействия с книгой.

Важная деталь: для книги используется `RaycastAll`, а не простой `Raycast`. Это нужно, чтобы книга открывалась даже если перед ее моделью есть декоративный или невидимый коллайдер.

### DesktopGrabber

Файл: `Assets/Scripts/Desktop/DesktopGrabber.cs`

Это главный desktop-аналог VR-захвата:

- луч идет из центра камеры;
- ПКМ работает как toggle: нажал - взял, нажал еще раз - отпустил;
- удерживаемый предмет переводится в kinematic-режим, чтобы физика не мешала ручному перемещению;
- предмет двигается перед камерой;
- каждый кадр проверяется, касается ли удерживаемая бутылка `IngredientZone`, а ложка - `StirZone`.

Именно здесь desktop-управление связывается с общей логикой котла.

## 5. Логика котла

### CauldronIngredientZone

Файл: `Assets/Scripts/Crafting/CauldronIngredientZone.cs`

Это зона добавления ингредиентов. Она принимает только бутылки, которые реально коснулись зоны котла.

Проверка сделана строго:

- берутся реальные коллайдеры бутылки;
- через `Physics.ComputePenetration` проверяется пересечение с зоной;
- если пересечения нет, бутылка не засчитывается.

Это решает проблему, когда бутылка могла исчезать перед котлом. Теперь она добавляется только при физическом попадании в `IngredientZone`.

### CauldronStirZone

Файл: `Assets/Scripts/Crafting/CauldronStirZone.cs`

Это зона проверки рецепта ложкой. Она работает отдельно от зоны ингредиентов:

- бутылки добавляются через `IngredientZone`;
- ложка проверяется через `StirZone`;
- рецепт запускается только если ложка удерживается игроком.

Также есть защита от спама: одно касание ложкой вызывает одну проверку, пока ложка не выйдет из зоны.

### CauldronReactions

Файл: `Assets/Scripts/Crafting/CauldronReactions.cs`

Этот класс связывает зоны котла, хранилище и проверку рецептов:

- принимает ингредиент;
- добавляет его в `CraftStorage`;
- запоминает instance id бутылки, чтобы одна бутылка не добавилась несколько раз;
- запускает `RecipeChecker.CheckRecipe()` только при перемешивании ложкой.

### CraftStorage

Файл: `Assets/Scripts/Crafting/CraftStorage.cs`

Это временное хранилище котла. В нем есть две сущности:

- список данных ингредиентов (`IngredientData`);
- список физических бутылок (`CollectableItem`), которые нужно вернуть на стол.

Так сделано специально: рецепт проверяется по данным, а визуальные объекты можно скрывать и возвращать независимо от проверки.

### RecipeChecker

Файл: `Assets/Scripts/Crafting/RecipeChecker.cs`

Это центр проверки рецептов:

- получает текущие ингредиенты из `CraftStorage`;
- сравнивает их с `RecipeData`;
- если рецепт правильный, вызывает `OnRecipeSuccess`;
- если неправильный, вызывает `OnRecipeFail`;
- после любой проверки возвращает бутылки и очищает котел.

Рецепты могут быть с важным порядком или без важного порядка. Сейчас для обычных рецептов порядок бросания бутылок не важен.

## 6. Предметы

### PickupItem

Файл: `Assets/Scripts/Interaction/PickupItem.cs`

Базовый класс подбираемых предметов. Он умеет:

- запоминать состояние Rigidbody;
- отключать гравитацию при удержании;
- возвращать физику при отпускании.

### CollectableItem

Файл: `Assets/Scripts/Crafting/CollectableItem.cs`

Это бутылка-ингредиент:

- хранит ссылку на `IngredientData`;
- знает, была ли уже добавлена в котел;
- умеет исчезать при попадании в котел;
- умеет возвращаться на стартовую позицию после проверки рецепта;
- восстанавливает физику, чтобы бутылка не зависала в воздухе.

### StirringSpoon

Файл: `Assets/Scripts/Crafting/StirringSpoon.cs`

Это ложка. Она наследуется от `PickupItem`, но не исчезает в котле. Ложка нужна только для запуска проверки рецепта в `StirZone`.

## 7. Книга рецептов

### RecipeBookViewer

Файл: `Assets/Scripts/Crafting/RecipeBookViewer.cs`

Книга сделана как плоское UI-меню поверх экрана, а не как 3D-страницы. Это ближе к обычным desktop-играм.

Когда книга открывается:

- движение игрока отключается;
- захват предметов отключается;
- курсор разблокируется;
- создается или включается `ScreenSpaceOverlay` Canvas;
- страницы листаются стрелками или UI-кнопками.

### RecipeBookCanvasUI

Файл: `Assets/Scripts/UI/RecipeBookCanvasUI.cs`

Этот класс выводит:

- название рецепта;
- большую картинку рецепта;
- список ингредиентов;
- иконки ингредиентов;
- номер страницы.

Если в инспекторе нет ручного списка страниц, книга сама берет рецепты из `RecipeChecker`.

## 8. Эффекты

Успешные рецепты запускают эффекты через событие `RecipeChecker.OnRecipeSuccess`.

Примеры:

- `MainPotionEffect` - основной визуальный эффект зелья.
- `FairyMistRecipeEffect` - эффект феи в тумане.
- `PoseidonWaterfallRecipeEffect` - водный эффект.
- `StormBottleVolleyRecipeEffect` - эффект бури.
- `SlimeRecipeEffect` / `SlimeAmbushRecipeEffect` / `WhisperNovaRecipeEffect` - эффекты слизней и магических реакций.

Неправильный рецепт запускает `RecipeChecker.OnRecipeFail`, а `CauldronFailEffect` окрашивает котел в красный цвет.

## 9. Рецепты в проекте

В проекте есть рецепты в `Assets/Data/Recipes`:

- `Костяной призрак слайма`: Пузырящаяся тварь + Болотная эссенция.
- `Шепчущий слизень`: Пузырящаяся тварь + Токсичная жижа + Чаша с шёпотом.
- `Голос тумана`: Чаша с шёпотом + Слепая настойка + Слеза феи.
- `Фея в тумане`: Слепая настойка + Jägermeister + Слеза феи.
- `Водопад Посейдона`: Болотная эссенция + Зелье разложения + Токсичная жижа.
- `Сердце бури`: Сгусток аномалии + Слеза феи + Живая гниль.
- `Главное зелье`: большой рецепт из основных ингредиентов.

Каждый рецепт - это `ScriptableObject RecipeData`, а каждый ингредиент - `ScriptableObject IngredientData`.

## 10. NPC Erika

Файл: `Assets/ErikaAnimationControl.cs`

NPC Erika подключена через Animator:

- по клавише `T` запускается движение/анимация;
- по успеху выбранного рецепта может запускаться другая анимация;
- после эффекта бури может запускаться `TakingPunch`.

Это показывает, что рецепты могут влиять не только на котел, но и на других персонажей сцены.

## 11. Связь с dvizki 2

`dvizki 3` сделан как desktop-адаптация логики из `dvizki 2`.

Общая идея между версиями:

- есть ингредиенты;
- есть котел;
- есть зона добавления ингредиентов;
- есть ложка/действие перемешивания;
- есть проверка рецепта;
- есть успешные и неуспешные реакции.

Отличие:

- в `dvizki 2` игрок взаимодействует через VR-контроллеры;
- в `dvizki 3` игрок взаимодействует через центральный reticle, ПКМ, клавиатуру и обычную камеру.

То есть архитектурно проекты похожи, но слой ввода разный. В `dvizki 3` слой ввода заменен на `DesktopGrabber`, `FirstPersonCC` и screen-space UI-книгу.

## 12. Что было вычищено

В рамках чистки desktop-версии:

- удалены XR/VR пакеты из `Packages`;
- удалены XR/VR ассеты и настройки, которые вызывали ошибки симулятора;
- из книги удален старый reflection-код для `XRGrabInteractable` и `XRSimpleInteractable`;
- удалены старые XR-hotspot элементы книги;
- удалены неиспользуемые overload-методы в `CauldronReactions`;
- удален неиспользуемый приватный метод `SetCollidersEnabled`;
- старые TMP world-тексты книги отключаются на старте;
- runtime-книга переведена на обычный UI Text, чтобы избежать ошибок TextCore/TMP в Unity 6.

## 13. Что проверено

Проверки после правок:

- `Assembly-CSharp` собирается без ошибок и предупреждений.
- `Assembly-CSharp-Editor` собирается без ошибок и предупреждений.
- В сцене нет missing scripts.
- В сцене есть ключевые компоненты: `IngredientZone`, `StirZone`, `CauldronReactions`, `CraftStorage`, `RecipeChecker`, `RecipeBookViewer`, `FirstPersonCC`, `ErikaAnimationControl`.
- В сцене есть 10 бутылок `CollectableItem` и 1 ложка `StirringSpoon`.
- В `Packages/manifest.json` нет XR Interaction Toolkit, OpenXR, XR Plug-in Management и XR simulation packages.

## 14. Как рассказывать преподавателю

Можно говорить так:

> Я сделал desktop-версию VR-механики. В оригинальной логике игрок в VR берет предметы руками, а здесь я заменил слой ввода на управление от первого лица. В центре экрана есть точка, из камеры идет raycast, по ПКМ предмет берется и удерживается перед камерой. При повторном нажатии ПКМ предмет отпускается.

> Бутылки не добавляются в инвентарь. Они физически переносятся в котел. Добавление происходит только когда коллайдер бутылки реально пересекается с `IngredientZone`. Это проверяется через `Physics.ComputePenetration`, поэтому бутылка не исчезает перед котлом.

> Когда бутылка попала в зону, `CauldronIngredientZone` передает ее в `CauldronReactions`. Там ингредиент сохраняется в `CraftStorage`, а сама бутылка скрывается. При этом хранится ссылка на физический объект, чтобы после проверки рецепта вернуть его на исходное место.

> Рецепт не проверяется при добавлении бутылок. Проверка запускается только ложкой: игрок берет ложку ПКМ и касается `StirZone`. Тогда `CauldronReactions` вызывает `RecipeChecker.CheckRecipe()`.

> `RecipeChecker` сравнивает текущий набор ингредиентов с `RecipeData`. Если рецепт совпал, вызывается событие `OnRecipeSuccess`, и нужные эффекты реагируют на него. Если рецепт не совпал, вызывается `OnRecipeFail`, и `CauldronFailEffect` подсвечивает котел красным.

> После любой проверки бутылки возвращаются на свои места. Это сделано через `CraftStorage.ReturnAllCollectedItems()`, который вызывает `ReturnToStart()` у каждой бутылки. Поэтому сцена готова к следующей попытке.

> Книга рецептов в desktop-версии сделана не 3D-страницами, а UI-панелью поверх экрана. Она открывается при наведении на книгу и нажатии E/F или ПКМ, блокирует движение игрока, показывает картинку рецепта, список ингредиентов и листается стрелками.

> От VR-версии осталась общая игровая логика: ингредиенты, котел, зоны, рецепты, эффекты. Но VR-ввод заменен на desktop-ввод. Поэтому `dvizki 3` можно рассматривать как адаптацию `dvizki 2` под обычный компьютер.

## 15. Короткая схема зависимостей

```text
FirstPersonCC
  -> движение игрока, камера, клавиатурное открытие книги

DesktopGrabber
  -> ПКМ взять/отпустить
  -> проверка удерживаемого предмета против зон котла

CollectableItem
  -> данные ингредиента
  -> исчезновение в котле
  -> возврат на старт

StirringSpoon
  -> предмет для запуска проверки

CauldronIngredientZone
  -> принимает только удерживаемые бутылки внутри зоны
  -> передает их в CauldronReactions

CauldronStirZone
  -> принимает только удерживаемую ложку внутри зоны
  -> просит CauldronReactions проверить рецепт

CauldronReactions
  -> добавляет ингредиенты в CraftStorage
  -> вызывает RecipeChecker при перемешивании

CraftStorage
  -> хранит IngredientData
  -> хранит ссылки на бутылки для возврата

RecipeChecker
  -> сравнивает ингредиенты с RecipeData
  -> вызывает OnRecipeSuccess или OnRecipeFail

Effects / ErikaAnimationControl / RecipeBookPinnedPhotoManager
  -> реагируют на события рецептов
```
